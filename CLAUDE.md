# SmartFlow — контекст проекта

Telegram Mini App: экосистема, где эксперты продают через SI-продавцов, а клиенты возвращаются каждый день через Бадди.
Вкладки: Комьюнити (сообщества, как Skool) · Маркетплейс · Бадди (центр) · Чаты · Настройки (бывший «Профиль»; там же «Мои бизнесы» → Офис). Карта и план подключений — `docs/ARCHITECTURE.md`.
Слоган: «From idea to selling. Faster.»

## Как работать с владелицей проекта
- Общаться по-русски, просто, без жаргона. Она не разработчик и работает с iPad/телефона.
- Настройки в сервисах (Railway, Cloudflare, Supabase, BotFather) она делает сама. Давай пошаговые инструкции: куда нажать, что вписать.
- Ключи и токены никогда не просить в чат и не писать в код. Только переменные окружения.
- Перед изменениями объяснять план; внешний вид менять только если об этом просили.
- Работа идёт через pull request в `main`; вливает она сама. Одна задача — одна сессия.
- Обсуждения и идеи — в обычном Claude; сюда приходит готовое ТЗ.

## Архитектура
```
Telegram → Cloudflare Worker (фронтенд, статика) → Railway (сервер Node/Express, все ключи)
                                                     ├→ Supabase (PostgreSQL)
                                                     ├→ OpenAI (ответы SI, server/services/si-engine.js)
                                                     ├→ Telegram Bot API (уведомления, server/services/telegram-bot.js)
                                                     └→ PostHog и Амплитуда (одни и те же цифры без личных данных; каждая работает, когда в Railway есть её ключ)
```
Правило: фронтенд общается только с сервером; сервер — со всеми сервисами.

## Переменные окружения (только имена)
- Railway: `TELEGRAM_BOT_TOKEN`, `JWT_SECRET`, `NODE_ENV=production`, `CORS_ORIGINS` (через запятую: `https://app.techsmartflow.com,https://my-project.gzhailaubekkyzy.workers.dev`),
  `DATABASE_URL` (Supabase Session pooler), `DB_DRIVER=postgres` (ровно это слово),
  `OPENAI_API_KEY` (сервер понимает и `OPEN_API_KEY`), необязательно `OPENAI_MODEL` (по умолчанию `gpt-4o-mini`), `BUDDY_MODEL` (модель Бадди, по умолчанию как `OPENAI_MODEL`), `GROUP_SUMMARY_MODEL` («Кратко» в группах, по умолчанию как `OPENAI_MODEL`; с Бадди не связано), `TEMPLATE_MODEL` (конструктор шаблона — самая сильная модель, запускается редко; по умолчанию как `OPENAI_MODEL`) и `TRANSCRIBE_MODEL` (расшифровка голосовых, по умолчанию `whisper-1`), `POSTHOG_API_KEY` (Project API key `phc_…`), `POSTHOG_HOST` (например `https://eu.i.posthog.com`; проверка — `/api/health` → `posthog.configured`),
  `AMPLITUDE_API_KEY` (API Key проекта Амплитуды; те же события, что в PostHog) и `AMPLITUDE_REGION` (`eu` по умолчанию или `us`; проверка — `/api/health` → `amplitude.configured`),
  `RESEND_API_KEY` (вход по почте: письма с кодом через resend.com) и `MAIL_FROM` (отправитель на подтверждённом в Resend домене, по умолчанию `SmartFlow <no-reply@techsmartflow.com>`); проверка — `/api/health` → `mail.configured`,
  `VAPID_PUBLIC_KEY` и `VAPID_PRIVATE_KEY` (уведомления из браузера, Web Push; пару создаёт владелица в панели поддержки → «Состояние системы» → «Создать ключи для уведомлений»; проверка — `/api/health` → `push.configured`), `GOOGLE_CLIENT_ID` (вход через Google: Google Cloud → OAuth client ID «Web application»; проверка — `/api/health` → `google.configured`), необязательно `VAPID_SUBJECT` и `WEB_APP_URL` (адрес приложения для ссылок в письмах; по умолчанию первый из `CORS_ORIGINS`),
  необязательно `DEFAULT_TZ_OFFSET_MINUTES` (часовой пояс клиента, если телефон его не сообщил; по умолчанию 300 = Алматы),
  `ADMIN_USERS` — номер владелицы из Профиля (`SF-48213`) или, надёжнее, её Telegram ID (цифры); несколько — через запятую: открывает «Панель поддержки».
  Тестовая копия: `APP_ENV=staging` (полоска «ТЕСТ», `/api/health` → `appEnv`), `TELEGRAM_BOT_USERNAME` (username её бота; по умолчанию `smartflow_ai_support_bot` — от него все ссылки `t.me/<бот>/app`).
  «Сначала одному человеку»: `FEATURES` (`имя:beta,имя2:all,имя3:off`) и `BETA_USERS` (номера `SF-…`) — `server/services/app-info.js`, в коде `appInfo.isOn(name, userId)` / `SF.feature(name)`.
  Проверка: `/api/health` → `openai.configured: true` значит, что сервер видит ключ; `commit` — первые 7 знаков запущенной версии (сверять с последним вливанием в `main`).
- Cloudflare (переменная сборки): `SMARTFLOW_API_URL` = адрес Railway с `https://`, без `/` в конце и без пробелов.

## Код
- Фронтенд: без фреймворка. `index.html`, `js/app.js` (каркас: меню, переходы, вход), `js/screens/*.js` (экраны вкладок; `admin.js` — панель поддержки внутри вкладки Профиль), `js/ui.js` (общие детали), `js/media.js` (фото), `js/data.js` (загрузка данных с сервера), `js/store.js` (состояние и кэш), `js/api-client.js`, `css/app.css`. **Выдуманных данных в интерфейсе нет** — только настоящие с сервера и понятные пустые экраны. В проектах (`projects`) хранятся SI-продавцы.
- Готовые файлы в репозитории: `css/tailwind.css` (Tailwind) и `js/icons.js` (иконки Lucide). После изменения классов или иконок: `npm run build`.
- Сервер: `server/index.js`, `server/routes/*`, `server/services/*`, `server/db/*` (SQLite локально / PostgreSQL в проде, один код), миграции в `server/db/migrations/`.
- Сборка для Cloudflare: `npm run build:pages` → `dist/`, настройки в `wrangler.jsonc`.
- Тесты: `npm test` (SQLite); на PostgreSQL: `TEST_DATABASE_URL=postgresql://... npm test` (пустая база).

## Дизайн и названия
- Логика логотипа: SI (красная точка) в центре соединяет людей (бирюзовые лепестки) вокруг. Словами это нигде не пишем — это видно по устройству интерфейса.
- В интерфейсе — «сценарии» / «условия» (если…, то…), **не «ветки»**: «ветки/дерево» — только наше внутреннее объяснение воронки (решение владелицы).
- **Решение 22 нояб.: «AI» вместо «SI» везде** («AI-продавец», «AI-мозг»; шаг 8 плана «Бизнес-режим 2.0»). Пока не переименовано — в коде и интерфейсе «SI», новые экраны пишем так же, чтобы не было смеси. Было: везде «SI», а не «ИИ/AI». Где нужна расшифровка — «SI — Super Intelligence». Исключение (решение владелицы 15 окт.): стандартный текст приглашения друзьям — «ИИ-Бадди», «ИИ-продавцы».
- На платформе (Офис, Маркетплейс, панель, документы) — «SI-продавец» (раньше «SI-консультант»). Клиенту SI называет себя ролью, которую выбрал эксперт (`projects.role_title`, всегда начинается с «SI-»; если пусто — «SI-консультант»). Во внутренних названиях кода и базы остаётся `consultant` / `projects`.
- Цвета: всё про SI — мягкий тёплый красный (`--si-bubble`, класс `text-si`, `.si-dot`); всё про людей — Тиффани (`text-brand`, `.chat-bubble-human`). В переписках людей (личных и группах, решение владелицы 21 нояб.): мои сообщения — тёмная Тиффани (`.chat-bubble-mine`), у каждого другого человека свой оттенок (`.chat-bubble-person` + `SF.personTone` → `.person-tone-0…6`: небо, лаванда, янтарь, зелёный, индиго, песок, слива; без красного и Тиффани). Красный не пугающий, только как метка SI или настоящая тревога.
- Тема светлая; тёмная — если в Telegram тёмный режим (`<html data-theme="dark">`). Цвета задаются переменными в `css/app.css`, классы `bg-page/card/sunken/raised`, `text-ink/ink-2/muted/faint`, `border-line/line-2` (см. `tailwind.config.js`). Не писать цвета вида `bg-[#090e17]`.
- Без рамки телефона: приложение на весь экран, на компьютере — колонка по центру.
- Персонажи (`images/mascots/`): `si-assistant` — поддержка, жалобы и предложения; `si-buddy` — главный экран и все уведомления; `si-consultant` — продаёт в чатах.

## Продуктовые решения владелицы
- Исходный документ продукта — «Smartflow — структура приложения» (у владелицы); в коде его суть — `docs/ARCHITECTURE.md`.
- Кто просто открыл приложение — попадает к Бадди. По ссылке SI-продавца, карточки или профиля — сразу туда.
- Ссылка SI-продавца открывает чат с ним **внутри приложения** (не в чате бота). SI пишет первым: приветствие, чем поможет, один вопрос. Бот только присылает уведомления с кнопкой в приложение.
- SI должен быть психологически приятнее живого продавца: тёплый, спокойный, не давит. В интерфейсе его не выпячиваем — только мягкая метка (защита от претензий «не сказали, что это бот»).
- Оплаты через платформу нет: у каждого SI-продавца своя ссылка на оплату, деньги идут автору напрямую.
- **Комьюнити вместо Инкубатора (решение владелицы 21 нояб., как Skool):** **часть 1 сделана 21 нояб.** (миграция 029): каталог открытых, скрытые по ссылке `K_<id>`, вход бесплатно / по заявке / платно по ссылке автора (разово или месяц, оплату подтверждает автор), лента с темами, закрепом и анонсами, комментарии с ответами, лайки без уведомлений, модераторы до 3, цифры автора, команда скрывает по жалобе; уведомления только на телефон (как группы); общего чата нет. Часть 2 — курсы, баллы, уровни, лидеры, напоминания. Сообщества создаёт только бизнес-профиль (сколько угодно), с курсами, механиками удержания и триггерами; группа в «Чатах» — обычная переписка, её создаёт любой. План — `docs/ARCHITECTURE.md`, «Комьюнити».
- **Бизнес-режим 2.0 (решения владелицы 21–22 нояб.; шаг 1 «основа данных» сделан 22 нояб., миграция 030: до 3 бизнесов с главным `is_primary`, продукты, SI-мозг у бизнеса, данные вниз через `inheritance.withInherited`; шаг 3 «пазл» сделан 22 нояб., миграция 031: в «Методологии» продавца — «что дополнить» (N из 8), разрешения «знает о бизнесе / обо мне», дополнения «тема → как отвечать» (`seller_notes`, работают и с купленной воронкой; «Научить SI отвечать на это» из «Мне написали»); пазл от автора воронки сделан 22 нояб., миграция 032: кусочки и вопросы задаёт автор воронки, ответы из Мозга подставляются сами, вопросы по одному, «Сохранить» → конфетти, воронка включается только по условию автора (`funnel_released`), при подключении спрашивает доступ к Мозгу; шаг 2 «новый Офис» сделан 22 нояб.: «Мои бизнесы» в Профиле, Офис = Мозг (о бизнесе, продукты, материалы) · Мои SI-продавцы · Помощник, внутри продавца Аналитика · Клиенты (Мне написали, все, календарь) · Рассылки · Методология с выбором продукта. Карта и шаги — `docs/ARCHITECTURE.md`, «Бизнес-режим 2.0»):** до 3 бизнесов у аккаунта (список и режим — в настройках Профиля); Офис бизнеса: Мозг · Мои AI-продавцы (это и есть «Мои шаблоны») · Помощник; аналитика — внутри каждого продавца, общей нет; AI-продавец = скелет автора шаблона + Мозг эксперта («пазл»: из Мозга подтягивается только разрешённое, в купленном шаблоне эксперт видит только что дополнить); шаблоны создаёт любой бизнес, публикуются **без проверки командой** (только скрытие по жалобе); вкладка Маркетплейса «Для бизнеса» видна всем; купленный шаблон — второй продавец; цифры публичного шаблона публичные, цифр продаж эксперта клиентам не показываем; автор видит, что дописали покупатели, без имён и внутрянки; версии с названиями, эксперт выбирает любую в любой момент.
- **Навигация (решения владелицы 23 нояб.):** вкладка «Профиль» стала **«Настройки»** (в коде вкладка `profile`, корневой экран `view` = список настроек): сверху фото и имя → «Мой профиль» (экран `me`, публичная страница), ниже режим Личный/Бизнес, **«Мои бизнесы»** (нажатие открывает Офис этого бизнеса **внутри Настроек**: экраны `office*` во вкладке `profile`, `SF.openIn('profile', 'office…')`), уведомления, поиск, язык, «Пригласить друзей» (экран `invite`), поддержка. **Маркетплейс — только смотреть и покупать** (специалисты и шаблоны; карточки плиткой, как в товарных маркетплейсах: 2 в ряд на телефоне, 3 на широком экране — картинка, цена, оффер, имя и оценка): ни Офиса, ни «Купленные / Мои шаблоны», ни «создать / опубликовать» там нет — всё это в Настройках → «Мои бизнесы» → Офис; экран Офиса, открытый во вкладке Маркетплейса, сам переходит в Настройки (кроме страницы шаблона `office-funnel`). Плашки с названием бизнеса в Офисе нет — название в заголовке. В «Мои SI-продавцы» две кнопки: **«Создать»** и **«Найти готовый»** (→ Маркетплейс → «Шаблоны ИИ-продавцов»). **Серых описаний под кнопками нет**: пояснение — только значком «i» (`SF.info(text)`, `SF.sectionTitle(icon, text, extra, infoText)`, подсказки полей) у нового для людей (пазл, шаблон, ниша, «Вопросы и ответы», сценарии, бизнес-режим, доступ к Мозгу, проверка на примере). Новые экраны пишем так же.

Установка на экран: `manifest.webmanifest`, `sw.js` (пока без кэша), иконки `images/icon-*.png`; в Настройках вне Telegram — «Установить на экран» (Android — системное окно, iPhone — инструкция «Поделиться → На экран „Домой“») и «Выйти». Telegram-аккаунты не привязываем (в Telegram пока никого — решение владелицы). **Часть 2 сделана** (миграция 037): уведомления на телефон и компьютер — канал `push` в `notify-service` (`push-service.js`, `sw.js`, ключи VAPID в Railway), в Настройках «Уведомления» и «Важное на почту», у Бадди — «Включите уведомления»; важное (`notifyUser(…, { important: true })`: встречи, оплата, клиент ждёт человека, ответ человека и поддержки) уходит письмом, если ни Telegram, ни уведомление не дошли (до 20 в сутки); на iPhone — только в установленном на экран. В Настройках (решение владелицы 23 нояб.) строк «Уведомления», «Важное на почту» и «Показывать меня в поиске» нет: включить уведомления — сообщением у Бадди, письма о важном и видимость в поиске — включены по умолчанию. **Часть 3 сделана:** «Войти через Google» на экране входа (`google-login.js`): страница Google → обратно на тот же адрес с `#id_token` → сервер проверяет подпись ключами Google, адресата `GOOGLE_CLIENT_ID`, одноразовое число и подтверждённую почту; тот же аккаунт Google — тот же аккаунт SmartFlow, а почта, с которой уже входили по коду, — тот же аккаунт (`auth_identities.provider = 'google'`). Без `GOOGLE_CLIENT_ID` кнопки нет. Проверка уведомлений: сразу после «Включить уведомления» приходит «Уведомления работают!» (`POST /api/push/test`); в панели поддержки → «Состояние системы» — «Проверить уведомление на моих устройствах» (устройства того аккаунта, с которого открыта панель). Бадди: «напомни …» — всегда напоминание, даже если ИИ забыл `remind_before` (было 23 нояб.: план без напоминания). **Цифра на значке** установленного приложения (решение владелицы 24 нояб.): непрочитанное у Бадди + переписки с людьми + группы (`badge-service.js`) уходит в каждом уведомлении (`sw.js` → `setAppBadge`), открытое приложение пересчитывает по красным отметкам вкладок (`SF.setAppBadge`); в Telegram — нет. «Напомни через N минут / часов / полчаса» — время считает сервер (`inMinutes` в `buddy-service.js`), не ИИ: 24 нояб. после полуночи ИИ ставил вчерашнюю дату, напоминание молча пропадало.
- Никаких выдуманных данных, отзывов и цифр для реальных людей: только настоящие данные или честное «скоро» / пустой экран.

## Важные решения и грабли
- Сервер раздаёт только `index.html`, `css/`, `js/`, `images/` — остальное 404 (раньше утекали исходники и база).
- Порядок CSS важен: `app.css`, затем `tailwind.css`.
- В Supabase на всех таблицах включён RLS без политик: публичный API Supabase закрыт, сервер (владелец таблиц) работает в обход RLS. Новые таблицы — тоже с RLS: в миграции блок `-- postgres-only:begin … -- postgres-only:end` (выполняется только на PostgreSQL).
- Фото (своё и SI-продавца) хранятся в таблице `media` и отдаются по `/api/media/:id`; принимаются только JPEG/PNG/WebP до 2 МБ (проверка по содержимому). Фронтенд заранее обрезает фото до 512×512.
- Имя, выбранное в приложении, лежит в `users.profile.displayName`: `users.display_name` перезаписывается из Telegram при каждом входе.
- Ссылки `startapp`: без параметра — Бадди; `<slug>` — чат с SI-продавцом; `C_<id>` — карточка; `P_<userId>` — профиль; `I_<projectId>` — «Мне написали» (внутри SI-продавца → «Клиенты»); `A_<feedbackId>` — жалоба в панели поддержки; `S_support` — чат «Поддержка»; `U_<userId>` — личная переписка с человеком; `G_<groupId>` — группа в Чатах; `J_<code>` — ссылка-приглашение в группу; `K_<communityId>` — сообщество; `KP_<postId>` — пост сообщества; `<slug>__<code>` — чат с SI-продавцом по ссылке с меткой источника; `R_<code>` — приглашение в SmartFlow (Бадди); `F_<id>` — готовая воронка в Офисе; `FREVIEW` — воронки на проверке (панель); `FSALES` — продажи моих воронок; `CAL` — календарь бизнеса (SI-продавец → «Клиенты» → «Календарь»); `ADMIN` — панель поддержки (ссылка для команды). Префиксы заглавные, slug всегда строчный.
- SI общается как живой тёплый SI-продавец; в интерфейсе SI не выпячиваем (без разделов «с SI / с людьми»), отмечаем мягко: точка на аватарке, оттенок сообщений, роль мелко в шапке чата. На прямой вопрос SI честно говорит, что он SI.
- Переписка с SI только после входа через Telegram (иначе чужие тратили бы OpenAI). Личность клиента — из входа, не из запроса.
- SI не берёт цены из старого поля `pricing_options` (там были заготовки) — только `price_label`, который ввёл эксперт.
- Бот пишет человеку, только если тот разрешил (`Telegram.WebApp.requestWriteAccess`); ошибка отправки не ломает основное действие. Разрешение спрашивается после сообщения SI-продавцу или человеку и когда Бадди добавил план (`SF.askWriteAccess(null, { auto: true })` — не чаще раза в 3 дня на устройстве, если человек отказал), а при «Связаться с человеком» и «Уведомления в Telegram → Включить» — всегда.
- **Все уведомления — сначала у Бадди** (таблица `notifications`, экран Бадди → «Уведомления»), потом то же на телефон через каналы доставки (сейчас один — Telegram; решение владелицы; Офис есть не у всех). Это делает `notify-service.notifyUser` (старый вызов `telegram-bot.notifyUser` ведёт туда же). **Исключение — группы в «Чатах» и сообщества** (решение владелицы 21 нояб.): их уведомления только на телефон (`buddy: false`), у Бадди будет своя функция; в приложении группы видны в «Чатах». В интерфейсе действие сценария — «Сообщить мне в SmartFlow».
- SI первым пишет через `POST /api/chat/:slug/start` (один раз, только в пустой чат). Без ключа OpenAI — простой шаблон приветствия.
- Если человек отказал боту в сообщениях, в Профиле есть «Уведомления в Telegram → Включить» (повторный запрос разрешения).
- **Не зависеть только от Telegram** (решение владелицы 16 окт.): уведомления идут «по каналам» (`server/services/notify-service.js`, список `CHANNELS`). Каналы сейчас: Telegram и веб-уведомления (Web Push, с 23 нояб.); новый (своё приложение) — ещё одна строка в списке; почта — запасной путь только для важного. Свои уведомления на телефон возможны только вне Telegram: веб-версия SmartFlow со своим входом (позже, см. «Что дальше»).
- **Новые сообщения на любом экране («пульс»):** пока приложение открыто, оно раз в 4 секунды спрашивает `GET /api/me/pulse` (один маленький запрос: когда менялись уведомления, переписки с людьми, чаты с SI-продавцами) и перезагружает только изменившееся; при возвращении в приложение — сразу (`js/data.js`). Раньше новое подтягивалось только в открытом чате — сообщения «доходили» через минуты.
- **Ничего не ждём бесконечно:** запрос с телефона — до 20 с (отправка — до 90 с, материал SI-мозга — до 3 мин), потом «Сервер долго не отвечает» с кодом; база — подключение до 10 с, ответ до 30 с; обрыв соединения с базой не роняет сервер (`pgPool.on('error')`). Медленные ответы (от 2 с) пишутся в логи Railway: `[SmartFlow Slow] GET /api/… 3200ms`; `/api/health` → `database.pingMs` — сколько идёт ответ от базы.
- **База Supabase в Сиднее (`ap-southeast-2`)**, сервер в US West — `pingMs` ≈ 180. Решение (16 окт.): пока реальных данных нет — новая пустая база во Франкфурте (`eu-central-1`, данные не копируем: там было 4 человека и 3 пробных SI-продавца) и сервер Railway в EU West; старую — на паузу, удалить через 1–2 недели (с ней уйдут и `backup_1010_…`). Пошагово — `docs/STAGING.md`. Бесплатный Supabase — 2 активных проекта: рабочий + тестовый, Сидней на паузе.
- **Ссылки на бота не пишем в код руками:** на сервере `telegramBot.miniAppLink(param)`, на телефоне `SF.appLink(param)` — у тестовой копии свой бот (сервер сообщает ссылку при входе, `app.appLink`).
- **Рискованные изменения — через `staging`:** PR в `staging` → владелица проверяет в тестовом боте → PR `staging` → `main`. Небольшие правки — как раньше сразу в `main`. Перед тестовой задачей подтянуть `main` в `staging`.
- **Ответы SI-продавца и Бадди приходят целиком** (решение владелицы 17 окт.): пока OpenAI пишет ответ (1–4 с), в чате «печатает…» с движущимися точками, как в WhatsApp. Ответ «на глазах», по словам (как в ChatGPT), не делаем и не предлагаем.
- Время сообщений в базе с точностью до секунды, поэтому id сообщений растут со временем (`newMessageId` в `chat-service.js`) — порядок не путается.
- В Supabase остались демо-записи первой версии (`is_demo = 1`, «Елена Воронова», «Громов»). В интерфейсе они не видны; dev-вход локально использует их.
- Проверка «Workers Builds» Cloudflare на pull request и сборки рабочих веток краснеют (`SMARTFLOW_API_URL is not set`): переменная сборки задана только для `main`. Это настройка Cloudflare, не код; владелице предложено отключить сборку других веток (Settings → Build → Branch control). Сборка проверяется локально: `SMARTFLOW_API_URL=https://example.up.railway.app npm run build:pages`.
- SI-мозг: хранится только текст материалов (решение владелицы), файлы не сохраняются. Поиск по смыслу считается в Node (работает и на SQLite, и на PostgreSQL); при большом объёме — перейти на pgvector. Материалы клиентам не отдаются, SI пересказывает их своими словами.
- Сервер требует Node 22+ (`engines` в package.json): библиотека чтения PDF `unpdf` на старых версиях не работает.
- Railway обновляется сам только при связи с GitHub (Settings → Source: «Auto deploys when pushed to GitHub»). 9–10 окт. связь терялась («Could not load branches»): вливания #6–#8 не доехали, сервер работал на #5. Починили переустановкой приложения Railway в GitHub. Если `/api/health` → `commit` не совпадает с `main` — проверять эту связь. Номер вида `4b5c8775` в карточке запуска Railway — внутренний номер запуска, не версия из GitHub; версию смотреть только в `/api/health` → `commit`.
- **Цифры: названия событий** (решение владелицы 18 нояб.): события PostHog и Амплитуды названы в коде (`analytics.capture('имя', …)`), графики построены на этих названиях. Любое добавление, переименование или удаление события (и его свойств) — отдельной строкой в описании PR и в списке событий `docs/ARCHITECTURE.md`, «Цифры: PostHog и Амплитуда».
- Неверный `DB_DRIVER` → сервер не запускается и пишет в логах Railway, что вписать (раньше молча работал на SQLite). Понимает `postgres`, `postgresql`, `pg`, `sqlite`.

## Поддержка: как найти человека с проблемой и починить только у него
Сделано. Руководство для команды (студента) — `docs/SUPPORT.md`; оно же коротко в панели («Как чинить»).
- **Номер человека** `SF-48213` (`users.support_code`) — внизу Профиля и в чате «Поддержка», не виден в публичном профиле.
- **Код ошибки** `K7P2` — у каждой ошибки сервера (в ответе `errorCode`) и сбоя на телефоне (нет связи, сломанный экран). Человек видит «(код K7P2)»; в логах Railway: `[SmartFlow Error] code=K7P2 user=SF-48213 …`; в таблице `error_log` (60 дней). Сломанный экран показывает код и кнопки «Написать в поддержку» / «Очистить данные на телефоне» вместо пустоты.
- **Жалоба** (`feedback`) сама прикладывает телефон и систему, версию Telegram, экран, последние коды ошибок (`context`). Бот пишет всей команде с кнопкой «Открыть». Ответ команды приходит человеку в чат «Поддержка» и в Telegram.
- **Панель поддержки** (ссылка `t.me/smartflow_ai_support_bot/app?startapp=ADMIN` или Профиль → «Панель поддержки»; `/api/admin/*`): жалобы, поиск людей, карточка человека (SI-продавцы, материалы, чаты, ошибки, что команда уже делала), ошибки по коду, журнал команды, команда, состояние системы, «Как чинить».
- **Роли:** владелица — из `ADMIN_USERS` в Railway; поддержка (студент) — владелица добавляет по номеру в панели («Команда», таблица `staff`). Блокировать людей и менять команду может только владелица.
- **Исправления** — готовые кнопки для одного человека (`server/services/support-fixes.js`): очистить данные на телефоне (`users.client_reset_at`), включить SI в чате, вернуть имя из Telegram, удалить фото, скрыть/показать/выключить SI-продавца, досчитать SI-мозг, блокировка. Каждое: сначала «было → станет» и число записей; сервер повторно считает записи и останавливается, если число другое; всё пишется в `admin_actions`. Просмотр переписки тоже пишется.
- Данные других людей в панели не сохраняются на телефоне (только в памяти).

**Как чинить у одного, не задев других.** Код у всех один, данные у каждого свои. Сначала понять, где проблема:
- на телефоне (кэш) → человек нажимает в Профиле «Очистить данные на этом устройстве»; данные на сервере остаются;
- в его данных → менять только его записи: кнопкой в панели поддержки (нет нужной кнопки — добавить новое исправление в `support-fixes.js`, а не править базу руками);
- в коде → чинить для всех: воспроизвести на тестовой базе, тест, PR, владелица вливает.

**Правила безопасности**
- Настоящую базу руками не правим. Если всё же нужно — только после резервной копии и только записи с номером этого человека.
- Перед исправлением данных проверяем, сколько записей изменится: ожидали 1, а выходит 300 — стоп.
- «Локально» — тестовая база в среде Claude, не настоящая. Настоящие данные клиентов к себе не копируем.
- Позже — тестовая копия приложения: второй сервер на Railway и вторая база на Supabase, чтобы проверять новую версию до того, как её получат все.
- Рискованные изменения можно включать сначала одному человеку (или владелице), потом всем.

## Разные модели ИИ для разных функций (решение обсуждено, не сделано)
Сейчас всё на OpenAI (один ключ и счёт, у владелицы включено автопополнение; нужен ещё месячный лимит расходов). План: у каждой функции своя переменная модели в Railway (например `SI_CHAT_MODEL`, `BUDDY_MODEL`). Чат SI — средняя модель (сравнить 2–3 на реальных диалогах); SI-мозг — `text-embedding-3-small` не менять (иначе пересчитывать все материалы); голос — расшифровка OpenAI; Бадди и проверка жалоб — самая дешёвая + бесплатная moderation; советы по воронке и брендолог — самая сильная. Другая компания (например Claude) — только если на сравнении продаёт заметно лучше: отдельный ключ и доработка сервера. Цены и названия моделей сверять перед подключением.
**Сравнение 20 нояб.** (12 типичных клиентов, нутрициолог с материалом «Частые вопросы», локальная копия): `gpt-4o-mini`, `gpt-4.1-mini`, `gpt-5.4-mini`. Все трое выдумывали «да, работаем с вегетарианцами» (нет в материалах), две писали стихи по просьбе, `gpt-4o-mini` отвечала англичанину по-русски. После уточнения инструкции SI (не угадывать «подходит ли», только по теме, язык клиента, без календаря время не предлагать) `gpt-5.4-mini` прошла всё без ошибок, `gpt-4o-mini` всё ещё выдумывает. Скорость у всех ≈1 с. Цена `gpt-5.4-mini` ≈ $0.75 / $4.50 за 1M токенов (≈5–7× дороже `gpt-4o-mini`), ≈0,4 цента за сообщение клиента. Рекомендация: `OPENAI_MODEL=gpt-5.4-mini`, `BUDDY_MODEL=gpt-4o-mini` (Бадди не сравнивали).

Перед сценариями — поле **«Общее описание»** методологии (как SI ведёт к покупке, идёт в инструкции SI). **Готовых условий нет — эксперт/маркетолог пишет условие словами** (SI проверяет и сообщения, и нажатые кнопки; для молчания — минуты и «после чего» словами или после другого сценария). **Ветки — универсальный инструмент** (решение владелицы: «удобный инструмент, который может применить почти каждый»; веток по умолчанию нет, создают эксперт или маркетолог): название ветки, действие «отправить мой текст или ссылку» (материал), «Клиент замолчал» после другой ветки — дерево. **Рассылки — отдельно** (анонсы: мероприятие, новость, акция; пока «скоро»). Панель поддержки → «Проверка микрофона» — владелице проверить запись на iPhone/iPad/Android и «Отправить результат команде». Подробно — `docs/ARCHITECTURE.md`, «Будильник».
- **Сделано (п. 4, календарь, миграция 012):** эксперт задаёт свободные окна себе и помощнику (дни + часы, своя постоянная ссылка Zoom у каждого), длительность и правила: может ли клиент сам перенести/отменить и за сколько часов (владелец и помощник отменяют всегда). Клиент записывается в чате с SI-продавцом: кнопка «Записаться» — только когда разговор дошёл до встречи (или «Моя встреча», если уже записан); время на 14 дней вперёд в часовом поясе телефона. Без двойной брони (проверка + уникальный индекс). Уведомления о записи/переносе/отмене и напоминание за час обеим сторонам (Бадди → Telegram). Статусы встречи и пустые поля под запись/расшифровку/анализ звонка. Подробно — `docs/ARCHITECTURE.md`, «Календарь». Время в PostgreSQL читается и пишется как UTC при любом часовом поясе сервера (`server/db/index.js`).
- **Люди пишут друг другу внутри SmartFlow (решение владелицы 14 окт., миграция 013):** цель — чтобы люди общались и обменивались именно здесь, **в Telegram не уводим**. Поиск: в Маркетплейсе — SI-продавцы; в «Чатах» — свои переписки и **любые люди** (по имени, @нику, строке под именем). Найти можно всех, кроме тех, кто выключил в Профиле «Показывать меня в поиске» (по умолчанию включено). Настроек «кто может мне писать» нет: первое сообщение приходит с вопросом «Принять / Заблокировать» (ответ = принять). Защита от спама: до ответа — не больше 3 сообщений, не больше 20 новых знакомств в день, блокировка (заблокированный не находит и не может писать, о блокировке не узнаёт), «Пожаловаться» — жалоба с последними сообщениями уходит команде (только так команда видит личную переписку) и сразу блокирует. Уведомление — у Бадди и в Telegram, одно на непрочитанные. В переписке — текст, голосовые (1,5 мин), фото и видео-кружки (30 сек). Поиск — по имени, @нику и ключевым словам из строки под именем и «О себе»; у каждого найденного две кнопки: «Профиль» и «Написать». **Бадди не предлагает писать людям и не называет людей** — может посоветовать SI-продавца (позже группу в Инкубаторе). Подробно — `docs/ARCHITECTURE.md`, «Люди: поиск и переписка».

Каждый пункт — отдельная сессия и PR.
- **Бизнес и помощник:** сущность «бизнес» над SI-продавцами (`projects`); SI-продавцы, клиенты, переписки, встречи принадлежат бизнесу. Каждому эксперту бизнес создаётся автоматически, данные переносятся (перед вливанием — резервная копия Supabase). Участники — таблица (строка на человека, роль владелец/помощник), сервер разрешает не больше одного помощника: лимит поднимается одной цифрой, без переделки. Помощник: «Мне написали», пауза/запуск SI, календарь, созвоны, карточки клиентов; не видит деньги и ссылки на оплату, не меняет SI-мозг, SI-продавцов, настройки; рассылки — с одобрения владельца. У сообщения — автор и тип (SI / клиент / владелец / помощник); у диалога — ответственный (SI или человек), на нём же пауза SI.
- **Права проверяет сервер**, не RLS: фронтенд ходит только на сервер, а сервер работает в обход RLS. RLS на таблицах остаётся закрытым замком.
- **Воронка:** 5 фиксированных статусов — «Не дообщались», «Пообщались, но не купили», «Ждут человека» (яркий), «Купили» (зелёный), «Отказ» (серый). У воронки SI-продавца есть цель-оффер: клиент ответил на оффер → «пообщались» (исход: купили / отказ / пообщались, но не купили); ответа на оффер нет → «не дообщались», путь ещё идёт. Обязательны сценарии «если…, то…» (на событиях журнала, делаются вместе с шагами воронки). Журнал событий — отдельная запись на каждое действие клиента (написал, возражение, передан человеку, записался, оплатил, отказ/ушёл). Постоянный внутренний ID клиента, поле согласия на передачу контактов. Сначала индекс «бизнес + статус», подсчёт по запросу и порции по 20–30; готовые счётчики — когда понадобятся (они плохо сочетаются с фильтром 7/30 дней). Даты во всех записях — под будущий архив старых переписок.
- **Голосовые:** главный риск — доступ к микрофону внутри Telegram (особенно iOS), сначала пробный образец. Расшифровка OpenAI принимает форматы iOS и Android; конвертация (ffmpeg) нужна, скорее всего, только для проигрывания. Лимит ~3 мин, хранение в Supabase Storage. Возражения из расшифровки — так же, как из текста.
- **Видео-вебинар (отложен 15 окт., всё — в `docs/WEBINAR.md`):** шаги воронки уже есть. Свой плеер (на iPhone не давать уходить в системный полноэкранный режим), процент досмотра по реально просмотренным секундам, защищённые ссылки и потоковая отдача (Cloudflare Stream или Bunny; цены сверить). Запись экрана запретить нельзя — обещаем «сложно скачать».
- **Календарь:** слоты эксперта, бронь в чате, постоянная ссылка Zoom, защита от двойной брони, часовые пояса, статусы встречи, пустые поля под запись/расшифровку/анализ звонка.
