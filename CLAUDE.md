# SmartFlow — контекст проекта

Telegram Mini App: экосистема, где эксперты продают через SI-консультантов (смарт-консультантов), а клиенты возвращаются каждый день через Бадди.
Вкладки: Инкубатор (позже; в документе — «Комьюнити») · Маркетплейс (+ Офис) · Бадди (центр) · Чаты · Профиль. Карта и план подключений — `docs/ARCHITECTURE.md`.
Слоган: «From idea to selling. Faster.»

## Как работать с владелицей проекта
- Общаться по-русски, просто, без жаргона. Она не разработчик и работает с iPad/телефона.
- Настройки в сервисах (Railway, Cloudflare, Supabase, BotFather) она делает сама. Давай пошаговые инструкции: куда нажать, что вписать.
- Ключи и токены никогда не просить в чат и не писать в код. Только переменные окружения.
- Перед изменениями объяснять план; внешний вид менять только если об этом просили.
- Работа идёт через pull request в `main`; вливает она сама. Одна задача — одна сессия.
- Просить вливать pull request только после итогового сообщения «готово». Если её pull request уже влит, а доработка пришла позже — новый pull request от свежего `main` (так было с #10 → #11: ссылка `ADMIN` не доехала).
- Обсуждения и идеи — в обычном Claude; сюда приходит готовое ТЗ.

## Архитектура
```
Telegram → Cloudflare Worker (фронтенд, статика) → Railway (сервер Node/Express, все ключи)
                                                     ├→ Supabase (PostgreSQL)
                                                     ├→ OpenAI (ответы SI, server/services/si-engine.js)
                                                     ├→ Telegram Bot API (уведомления, server/services/telegram-bot.js)
                                                     └→ PostHog (пока НЕ подключён)
```
Правило: фронтенд общается только с сервером; сервер — со всеми сервисами.

## Переменные окружения (только имена)
- Railway: `TELEGRAM_BOT_TOKEN`, `JWT_SECRET`, `NODE_ENV=production`, `CORS_ORIGINS` (через запятую: `https://app.techsmartflow.com,https://my-project.gzhailaubekkyzy.workers.dev`),
  `DATABASE_URL` (Supabase Session pooler), `DB_DRIVER=postgres` (ровно это слово),
  `OPENAI_API_KEY` (сервер понимает и `OPEN_API_KEY`), необязательно `OPENAI_MODEL` (по умолчанию `gpt-4o-mini`), `POSTHOG_API_KEY`, `POSTHOG_HOST`,
  `ADMIN_USERS` — номер владелицы из Профиля (`SF-48213`; несколько — через запятую): открывает «Панель поддержки».
  Проверка: `/api/health` → `openai.configured: true` значит, что сервер видит ключ; `commit` — первые 7 знаков запущенной версии (сверять с последним вливанием в `main`).
- Cloudflare (переменная сборки): `SMARTFLOW_API_URL` = адрес Railway с `https://`, без `/` в конце и без пробелов.

## Код
- Фронтенд: без фреймворка. `index.html`, `js/app.js` (каркас: меню, переходы, вход), `js/screens/*.js` (экраны вкладок; `admin.js` — панель поддержки внутри вкладки Профиль), `js/ui.js` (общие детали), `js/media.js` (фото), `js/data.js` (загрузка данных с сервера), `js/store.js` (состояние и кэш), `js/api-client.js`, `css/app.css`. **Выдуманных данных в интерфейсе нет** — только настоящие с сервера и понятные пустые экраны. В проектах (`projects`) хранятся SI-консультанты.
- Готовые файлы в репозитории: `css/tailwind.css` (Tailwind) и `js/icons.js` (иконки Lucide). После изменения классов или иконок: `npm run build`.
- Сервер: `server/index.js`, `server/routes/*`, `server/services/*`, `server/db/*` (SQLite локально / PostgreSQL в проде, один код), миграции в `server/db/migrations/`.
- Сборка для Cloudflare: `npm run build:pages` → `dist/`, настройки в `wrangler.jsonc`.
- Тесты: `npm test` (SQLite); на PostgreSQL: `TEST_DATABASE_URL=postgresql://... npm test` (пустая база).

## Дизайн и названия
- Логика логотипа: SI (красная точка) в центре соединяет людей (бирюзовые лепестки) вокруг. Словами это нигде не пишем — это видно по устройству интерфейса.
- Везде «SI», а не «ИИ/AI». Где нужна расшифровка — «SI — Super Intelligence».
- Цвета: всё про SI — мягкий тёплый красный (`--si-bubble`, класс `text-si`, `.si-dot`); всё про людей — Тиффани (`text-brand`, `.chat-bubble-human`). Красный не пугающий, только как метка SI или настоящая тревога.
- Тема светлая; тёмная — если в Telegram тёмный режим (`<html data-theme="dark">`). Цвета задаются переменными в `css/app.css`, классы `bg-page/card/sunken/raised`, `text-ink/ink-2/muted/faint`, `border-line/line-2` (см. `tailwind.config.js`). Не писать цвета вида `bg-[#090e17]`.
- Без рамки телефона: приложение на весь экран, на компьютере — колонка по центру.
- Персонажи (`images/mascots/`): `si-assistant` — поддержка, жалобы и предложения; `si-buddy` — главный экран и все уведомления; `si-consultant` — продаёт в чатах.

## Продуктовые решения владелицы
- Исходный документ продукта — «Smartflow — структура приложения» (у владелицы); в коде его суть — `docs/ARCHITECTURE.md`.
- Кто просто открыл приложение — попадает к Бадди. По ссылке консультанта, карточки или профиля — сразу туда.
- Создать своего SI-консультанта: Маркетплейс → кнопка «Создать своего SI-консультанта» (если Офис не открыт — сначала условия, после согласия сразу форма). Внутри Офиса — «Создать SI-консультанта».
- Ссылка консультанта открывает чат с ним **внутри приложения** (не в чате бота). SI пишет первым: приветствие, чем поможет, один вопрос. Бот только присылает уведомления с кнопкой в приложение.
- SI должен быть психологически приятнее живого продавца: тёплый, спокойный, не давит. В интерфейсе его не выпячиваем — только мягкая метка (защита от претензий «не сказали, что это бот»).
- Оплаты через платформу нет: у каждого консультанта своя ссылка на оплату, деньги идут автору напрямую.
- «Комьюнити» из документа в приложении называется «Инкубатор» и пока не делается (вкладка помечена «скоро»).
- Никаких выдуманных данных, отзывов и цифр для реальных людей: только настоящие данные или честное «скоро» / пустой экран.

## Важные решения и грабли
- Сервер раздаёт только `index.html`, `css/`, `js/`, `images/` — остальное 404 (раньше утекали исходники и база).
- Порядок CSS важен: `app.css`, затем `tailwind.css`.
- В Supabase на всех таблицах включён RLS без политик: публичный API Supabase закрыт, сервер (владелец таблиц) работает в обход RLS. Новые таблицы — тоже с RLS: в миграции блок `-- postgres-only:begin … -- postgres-only:end` (выполняется только на PostgreSQL).
- Фото (своё и SI-консультанта) хранятся в таблице `media` и отдаются по `/api/media/:id`; принимаются только JPEG/PNG/WebP до 2 МБ (проверка по содержимому). Фронтенд заранее обрезает фото до 512×512.
- Имя, выбранное в приложении, лежит в `users.profile.displayName`: `users.display_name` перезаписывается из Telegram при каждом входе.
- Ссылки `startapp`: без параметра — Бадди; `<slug>` — чат с консультантом; `C_<id>` — карточка; `P_<userId>` — профиль; `I_<projectId>` — «Мне написали»; `A_<feedbackId>` — жалоба в панели поддержки; `S_support` — чат «Поддержка»; `ADMIN` — панель поддержки (ссылка для команды). Префиксы заглавные, slug всегда строчный.
- SI общается как живой тёплый консультант; в интерфейсе SI не выпячиваем (без разделов «с SI / с людьми»), отмечаем мягко: точка на аватарке, оттенок сообщений, роль мелко в шапке чата. На прямой вопрос SI честно говорит, что он SI.
- Переписка с SI только после входа через Telegram (иначе чужие тратили бы OpenAI). Личность клиента — из входа, не из запроса.
- SI не берёт цены из старого поля `pricing_options` (там были заготовки) — только `price_label`, который ввёл эксперт.
- Бот пишет человеку, только если тот разрешил (`Telegram.WebApp.requestWriteAccess`); ошибка отправки не ломает основное действие.
- SI первым пишет через `POST /api/chat/:slug/start` (один раз, только в пустой чат). Без ключа OpenAI — простой шаблон приветствия.
- Если человек отказал боту в сообщениях, в Профиле есть «Уведомления в Telegram → Включить» (повторный запрос разрешения).
- Время сообщений в базе с точностью до секунды, поэтому id сообщений растут со временем (`newMessageId` в `chat-service.js`) — порядок не путается.
- В Supabase остались демо-записи первой версии (`is_demo = 1`, «Елена Воронова», «Громов»). В интерфейсе они не видны; dev-вход локально использует их.
- Проверка «Workers Builds» Cloudflare на pull request и сборки рабочих веток краснеют (`SMARTFLOW_API_URL is not set`): переменная сборки задана только для `main`. Это настройка Cloudflare, не код; владелице предложено отключить сборку других веток (Settings → Build → Branch control). Сборка проверяется локально: `SMARTFLOW_API_URL=https://example.up.railway.app npm run build:pages`.
- SI-мозг: хранится только текст материалов (решение владелицы), файлы не сохраняются. Поиск по смыслу считается в Node (работает и на SQLite, и на PostgreSQL); при большом объёме — перейти на pgvector. Материалы клиентам не отдаются, SI пересказывает их своими словами.
- Сервер требует Node 22+ (`engines` в package.json): библиотека чтения PDF `unpdf` на старых версиях не работает.
- Railway обновляется сам только при связи с GitHub (Settings → Source: «Auto deploys when pushed to GitHub»). 9–10 окт. связь терялась («Could not load branches»): вливания #6–#8 не доехали, сервер работал на #5. Починили переустановкой приложения Railway в GitHub. Если `/api/health` → `commit` не совпадает с `main` — проверять эту связь.
- Неверный `DB_DRIVER` → сервер не запускается и пишет в логах Railway, что вписать (раньше молча работал на SQLite). Понимает `postgres`, `postgresql`, `pg`, `sqlite`.
- `.antigravity/` в репозитории содержит логи чатов другого инструмента; в истории git есть старый токен бота (уже отозван).

## Поддержка: как найти человека с проблемой и починить только у него
Сделано. Руководство для команды (студента) — `docs/SUPPORT.md`; оно же коротко в панели («Как чинить»).
- **Номер человека** `SF-48213` (`users.support_code`) — внизу Профиля и в чате «Поддержка», не виден в публичном профиле.
- **Код ошибки** `K7P2` — у каждой ошибки сервера (в ответе `errorCode`) и сбоя на телефоне (нет связи, сломанный экран). Человек видит «(код K7P2)»; в логах Railway: `[SmartFlow Error] code=K7P2 user=SF-48213 …`; в таблице `error_log` (60 дней). Сломанный экран показывает код и кнопки «Написать в поддержку» / «Очистить данные на телефоне» вместо пустоты.
- **Жалоба** (`feedback`) сама прикладывает телефон и систему, версию Telegram, экран, последние коды ошибок (`context`). Бот пишет всей команде с кнопкой «Открыть». Ответ команды приходит человеку в чат «Поддержка» и в Telegram.
- **Панель поддержки** (ссылка `t.me/smartflow_ai_support_bot/app?startapp=ADMIN` или Профиль → «Панель поддержки»; `/api/admin/*`): жалобы, поиск людей, карточка человека (консультанты, материалы, чаты, ошибки, что команда уже делала), ошибки по коду, журнал команды, команда, состояние системы, «Как чинить».
- **Как заходит поддержка:** со своего Telegram (телефон или Telegram Desktop) по ссылке `?startapp=ADMIN` или по кнопке «Открыть» в сообщении бота о жалобе. Отдельного сайта нет (возможно позже: `support.techsmartflow.com` со входом через Telegram).
- **Роли:** владелица — из `ADMIN_USERS` в Railway; поддержка (студент) — владелица добавляет по номеру в панели («Команда», таблица `staff`). Блокировать людей и менять команду может только владелица.
- **Исправления** — готовые кнопки для одного человека (`server/services/support-fixes.js`): очистить данные на телефоне (`users.client_reset_at`), включить SI в чате, вернуть имя из Telegram, удалить фото, скрыть/показать/выключить консультанта, досчитать SI-мозг, блокировка. Каждое: сначала «было → станет» и число записей; сервер повторно считает записи и останавливается, если число другое; всё пишется в `admin_actions`. Просмотр переписки тоже пишется.
- Данные других людей в панели не сохраняются на телефоне (только в памяти).

**Как чинить у одного, не задев других.** Код у всех один, данные у каждого свои. Сначала понять, где проблема:
- на телефоне (кэш) → человек нажимает в Профиле «Очистить данные на этом устройстве»; данные на сервере остаются;
- в его данных → менять только его записи: кнопкой в панели поддержки (нет нужной кнопки — добавить новое исправление в `support-fixes.js`, а не править базу руками);
- в коде → чинить для всех: воспроизвести на тестовой базе, тест, PR, владелица вливает.

**Правила безопасности**
- Настоящую базу руками не правим. Если всё же нужно — только после резервной копии и только записи с номером этого человека.
- Перед исправлением данных проверяем, сколько записей изменится: ожидали 1, а выходит 300 — стоп.
- «Локально» — тестовая база в среде Claude, не настоящая. Настоящие данные клиентов к себе не копируем.
- Позже — тестовая копия приложения: второй сервер на Railway и вторая база на Supabase, чтобы проверять новую версию до того, как её получат все.
- Рискованные изменения можно включать сначала одному человеку (или владелице), потом всем.

## Разные модели ИИ для разных функций (решение обсуждено, не сделано)
Сейчас всё на OpenAI (один ключ и счёт, у владелицы включено автопополнение; нужен ещё месячный лимит расходов). План: у каждой функции своя переменная модели в Railway (например `SI_CHAT_MODEL`, `BUDDY_MODEL`). Чат SI — средняя модель (сравнить 2–3 на реальных диалогах); SI-мозг — `text-embedding-3-small` не менять (иначе пересчитывать все материалы); голос — расшифровка OpenAI; Бадди и проверка жалоб — самая дешёвая + бесплатная moderation; советы по воронке и брендолог — самая сильная. Другая компания (например Claude) — только если на сравнении продаёт заметно лучше: отдельный ключ и доработка сервера. Цены и названия моделей сверять перед подключением.

## До открытого запуска (со стороны владелицы)
- Включить панель поддержки: свой номер из Профиля → Railway → Variables → `ADMIN_USERS` (см. `docs/SUPPORT.md`), проверить ссылку `t.me/smartflow_ai_support_bot/app?startapp=ADMIN`, разрешить боту сообщения (Профиль → «Уведомления в Telegram»), добавить студента в «Команду».
- Проверить `/api/health` → `openai.configured: true`; поставить месячный лимит расходов в OpenAI.
- Пользовательское соглашение и политика обработки данных (ссылки добавить на экран условий Офиса).
- Юрист: хранение личных данных граждан РК на серверах в РК.
- Резервные копии базы в Supabase (зависит от тарифа).
