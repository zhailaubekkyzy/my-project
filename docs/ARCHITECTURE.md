# SmartFlow — устройство приложения и план подключений

Этот файл — карта: что уже работает, что пока показано на демо-данных и куда что подключать дальше.
Подробная логика продукта — в документе «Smartflow — структура приложения».

## Нижнее меню (слева направо)

| Место | Вкладка | Сейчас | Файл |
|---|---|---|---|
| 1 | Инкубатор | Место зарезервировано, помечено «скоро» | будет `js/screens/incubator.js` |
| 2 | Маркетплейс (+ Офис) | Витрина, карточка, «Купить», Офис | `js/screens/marketplace.js`, `js/screens/office.js` |
| 3 | Бадди (центр, главный экран) | Следующий шаг, уведомления, окошки разделов | `js/screens/buddy.js` |
| 4 | Чаты | Чаты с SI и с людьми, плашка оффера | `js/screens/chats.js` |
| 5 | Профиль | Профиль-лендинг, фото, доверие | `js/screens/profile.js` |

Инкубатор включается одной строкой: `enabled: true` в списке `TABS` в `js/app.js`, плюс файл экрана.

## Как устроен фронтенд

```
index.html
 ├ js/api-client.js      связь с сервером (Railway)
 ├ js/store.js           состояние и демо-данные; навигация (стек экранов в каждой вкладке)
 ├ js/icons.js           иконки (собирается: npm run build)
 ├ js/ui.js              общие детали: аватар, метка SI, уведомления Бадди, процент доверия
 ├ js/media.js           фото: выбор на телефоне → квадрат 512×512 → JPEG → загрузка
 ├ js/screens/*.js       экраны вкладок, каждый регистрируется в window.SF.screens
 └ js/app.js             каркас: нижнее меню, переходы, кнопка «Назад» Telegram, вход
```

- Переходы: `SF.go('chats')` — вкладка, `SF.push('consultant', { id })` — экран глубже, `SF.back()` — назад.
  Кнопка «Назад» в шапке Telegram работает так же.
- Всё, что вводят люди, выводится через `SF.esc()` (защита от вставки чужого кода).
- Ссылки наружу: `t.me/smartflow_ai_support_bot/app?startapp=c_<id>` открывает карточку консультанта.

## Что уже настоящее (сервер и база), а что демо

| Данные | Где хранится |
|---|---|
| Вход через Telegram, пользователь, его внутренний ID | сервер, таблицы `users`, `auth_identities` |
| **Своё фото** | сервер: `POST /api/me/photo`, таблица `media` |
| **Профиль-лендинг** (имя, о себе, регалии, результаты, ссылки, кнопка оффера) | сервер: `PUT /api/me/profile`, `users.profile` |
| **Мои SI-консультанты**: имя, роль (всегда «SI-…»), цель, инструкции, лимит, ссылка | сервер: таблица `projects` |
| **Фото SI-консультанта** | сервер: `POST /api/projects/:id/photo`, таблица `media` |
| Нажатие «Связаться с человеком», сообщения клиента в чате Елены | сервер: `direct_inquiries`, `conversations` |
| Каталог Маркетплейса, отзывы, цифры | демо (`js/store.js` → `marketplace`) |
| Клиенты, аналитика, рассылки, «Мне написали» в Офисе | демо (`js/store.js` → `expert`) |
| SI-мозг (список материалов) | демо (`js/store.js` → `office.brain`) |
| Ответы SI | заглушка по ключевым словам (`js/ai-engine.js`, `server/routes/public.js`) |
| Флажок «бизнес-профиль открыт» | только на устройстве |

Фото хранятся в базе (до 2 МБ, только JPEG/PNG/WebP, проверка по содержимому файла).
Переезд в отдельное хранилище (Supabase Storage или Cloudflare R2) — правка одного файла:
`server/services/media-service.js`.

## План подключений (по порядку)

1. **Настоящие данные вместо демо.**
   Каталог Маркетплейса — из `projects` (добавить поля «показывать на витрине», оффер, цена, пробный период).
   Клиенты, переписки, «Мне написали» в Офисе — из уже готовых маршрутов `/api/projects/:id/clients`,
   `/api/projects/:id/conversations`, `.../inquiries`. Флажок бизнес-профиля — на сервер.
2. **OpenAI.** Новый `server/services/si-engine.js` вместо ключевых слов в `server/routes/public.js`
   и `js/ai-engine.js`. Ответ строится из цели, инструкций, лимита и разрешённых материалов SI-мозга.
   Правило «не знаю → спрошу эксперта»: вопрос попадает эксперту, Бадди показывает кнопку «Ответить».
   Голосовые — через Whisper на сервере. Ключ `OPENAI_API_KEY` — только в Railway.
3. **SI-мозг.** Загрузка PDF, текстов, аудио/видео с расшифровкой. Таблицы `brain_materials`
   и `consultant_materials` (кому что открыто). Поиск по смыслу — расширение pgvector в Supabase.
   Большие файлы — в отдельном хранилище, не в базе.
4. **Уведомления Бадди через бота.** Сообщения в Telegram от @smartflow_ai_support_bot;
   лимит в день, «собирать рассылки в одну папку», своё время доставки.
5. **Плашка альтернативного оффера на сервере.** Метки возражений, правило «один оффер за раз»,
   сценарий 3 (нет возражения и покупки → через заданное время). Эксперт видит только факт ухода и причину.
6. **PostHog.** События без личных данных: вход, открытие Офиса, создание SI, сообщение клиента,
   ответ SI, «Связаться с человеком», показ и скрытие плашки.
7. **Языки RU/EN.** Тексты интерфейса — в отдельные словари; язык интерфейса и язык общения SI
   с клиентами — разные настройки (`users.profile.language` уже есть).
8. **Профиль-лендинг для соцсетей.** Публичная страница с превью; SI-брендолог (интервью → профиль).
9. **Жалобы и предложения.** Чат SI-ассистента пишет в таблицу `feedback`; простая админ-панель.
10. **Инкубатор** (в документе — «Комьюнити»). Вкладка 1: группы до 6 человек, SI-тамада, серия дней, лиги, наставники.
11. **Оплата через платформу** — позже. Сейчас эксперты и авторы указывают свои ссылки на оплату.

## Важно помнить

- Цифровые товары внутри Telegram Mini App по правилам Telegram оплачиваются через Telegram Stars.
  Пока платформа не принимает платежи, это нас не касается; при подключении — проверить заранее.
- Личные данные граждан Казахстана по закону должны храниться на серверах в РК — вопрос к юристу
  до массового запуска.
- RLS (закрытый публичный доступ Supabase) теперь включается в миграциях: блок
  `-- postgres-only:begin … -- postgres-only:end` выполняется только на PostgreSQL.
