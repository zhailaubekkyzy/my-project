- **Агрегированная аналитика:** Результаты воронки БЕЗ персональных данных клиентов экспертов.
- **AI-Анализатор узких мест:** Автоматические подсказки по оптимизации этапов воронки.
- **Когортный Ретеншн (Retention):** Таблица удержания экспертов по месяцам (M1–M5).

## 🏗️ Архитектура Этапа 1 (Backend, База Данных & Безопасность)

### 1. Архитектура аккаунтов (Single Source of Truth)
- **SmartFlow Core Backend** является единственным источником истины.
- Каждому пользователю присваивается постоянный внутренний идентификатор: `usr_<uuid>` (сохраняется при повторных входах).
- Telegram ID хранится в таблице `auth_identities` как один из привязанных методов входа. Позже к тому же аккаунту можно бесшовно подключить Web/Email/Google без смены внутреннего ID.
- Авторизация Telegram проверяется криптографически по алгоритму **HMAC-SHA256** с использованием секретного ключа бота. Данные старше 24 часов (`auth_date`) автоматически отклоняются.
- Роли (`expert`, `marketer`) контролируются строго на сервере и подписываются в JWT-токене. Клиент не может назначить себе роль в обход сервера.

### 2. Разделение шаблона маркетолога и экземпляра эксперта
- **Шаблон маркетолога (`funnel_templates`):** Методология, шаги воронки, системный промпт ИИ-клона, база знаний и рекомендованная цена.
- **Экземпляр эксперта (`projects`):** При подписке эксперта на воронку создается независимый проект эксперта. Эксперт кастомизирует свои тарифы, знания и настройки. Изменения эксперта изолированы от шаблона.
- **Подписка на шаблон маркетолога НЕ даёт ему доступа к данным эксперта.** Создатель шаблона не видит клиентов, переписок и внутренних настроек эксперта.

### 3. Фундамент для будущего приглашения маркетолога в проект эксперта
- Таблица `project_members` и middleware `checkProjectAccess` поддерживают гранулярные права доступа:
  - `funnel:read` / `funnel:write` — просмотр и редактирование настроек воронки;
  - `analytics:read` — просмотр аналитики проекта;
  - `conversations:read` / `conversations:write` — просмотр клиентов, переписок и перехват диалога (*Human Takeover*);
  - `*` — полный доступ (только владелец проекта).
- Сейчас доступ к проекту имеет **только эксперт-владелец**. В будущем эксперт сможет выдать доступ маркетологу или ассистенту и в любой момент его отозвать.

### 4. Подписка SmartFlow vs Подписка на воронку маркетолога
- **Подписка SmartFlow (`platform_subscriptions`):** Доступ к платформе SmartFlow. Для первых 100 пользователей действует бесплатный тариф `founder_free_100`.
- **Подписка на воронку маркетолога (`funnel_subscriptions`):** Каждый маркетолог сам определяет стоимость и длительность бесплатного триала (по умолчанию 14 дней).
- **Правило сохранения данных при отмене:** При отмене подписки данные **НЕ удаляются**. Доступ сохраняется до конца текущего оплаченного периода. Вся история, клиенты и настройки остаются в безопасности в базе данных.

### 5. Изоляция клиентов и закрытых API
- Клиенты взаимодействуют с опубликованным ИИ-продавцом через публичный эндпоинт `/api/public/funnels/:slug/chat`.
- Публичный API отдает только безопасные данные (имя эксперта, приветствие ИИ, тарифы).
- Внутренние системные промпты, база знаний, ID владельца и чужие переписки строго скрыты.
- Попытки обращения клиента к эндпоинтам `/api/projects`, `/api/templates`, `/api/expert` без авторизации блокируются кодом `401 Unauthorized`.

## 🛠️ Инструкция по запуску, тестированию и миграциям

### 1. Установка зависимостей и запуск сервера
```bash
# Установка пакетов
npm install

# Запуск сервера SmartFlow в режиме разработки
npm run dev

# Запуск в production
npm start
```
Сервер будет доступен по адресу: `http://localhost:3000` (API: `http://localhost:3000/api/health`).

### Сборка фронтенда
CSS (Tailwind) и иконки (Lucide) собираются заранее, без CDN. Готовые `css/tailwind.css` и `js/icons.js` лежат в репозитории.
После изменения классов или иконок в `index.html` / `js/*.js` пересоберите их:
```bash
npm run build          # иконки + Tailwind CSS
npm run build:pages    # сборка dist/ для Cloudflare Pages (нужна переменная SMARTFLOW_API_URL)
```
Cloudflare (Workers с раздачей статики, настройки в `wrangler.jsonc`): Build command `npm run build:pages`, Deploy command `npx wrangler deploy`, переменная сборки `SMARTFLOW_API_URL` = адрес backend на Railway.
На Railway задайте `CORS_ORIGINS` = адрес сайта на Pages (например `https://smartflow.pages.dev`).

### 2. Автоматическое тестирование безопасности (14 проверок)
Тесты запускаются на отдельной изолированной тестовой базе данных:
```bash
# Запуск полного набора тестов
npm test

# Формирование отчета проверок безопасности
npm run verify
```

### 3. Версионируемые миграции базы данных
Миграции расположены в каталоге `server/db/migrations/`:
- `001_initial_schema.sql` — Полная схема таблиц, связей и индексов.
- `002_seed_demo_data.sql` — Начальные шаблоны и демоданные (с флагом `is_demo = 1`).

При запуске сервера мигратор автоматически применяет только новые миграции. Ручной запуск:
```bash
npm run migrate
```

### 4. Резервное копирование и восстановление (Backup & Restore)
```bash
# Создание резервной копии базы данных (сохраняется в backups/smartflow-backup-<timestamp>.json)
npm run backup

# Восстановление базы данных из резервной копии
node scripts/restore.js backups/smartflow-backup-YYYY-MM-DD.json
```
